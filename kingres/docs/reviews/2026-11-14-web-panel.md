## Summary

No script execution, markup injection, token disclosure or credential leak was found. Every API string reaches the DOM
through Vue text interpolation; no `v-html`, `innerHTML`, dynamic component name from data, data-built `href`/`src`, or
`eval` exists in `src/` or in the bundle. The defects found are mostly in destructive-action safeguards, display
spoofing, handover between users, and a few correctness and accessibility problems. Nothing is rated critical. Two are
rated high.

## Findings

### W-01 high - Network rules applied with no confirmation, by Enter, with no lock-out warning

File: `src/components/security/NetworkPanel.vue` (form at line ~110 `@submit.prevent="save.run()"`, the submit
`GateButton` "Apply on all servers", empty-list text at ~line 170).

What is wrong: the rules editor is one `<form>` whose submit replaces the cluster-wide network access list and
starts a task on every server. There is no confirmation dialog and no statement of consequence. Pressing Enter in
any text input of the form (databases, users, address, comment) submits it. The editor does not warn when the new
list would remove the address the administrator is connecting from, has no `reject` or `cert` surprise check, or is
empty (the table says "Nobody can connect over the network." but the button stays enabled). Replacing the rules is
one of the actions the project lists as needing a consequence-stating confirmation.

Trigger: Security > Network access, focus the "Rule 1 comment" field, type, press Enter.

Reproduced: yes. Observed `PUT /api/v1/settings/network-access` with the whole rule list fired immediately, no
dialog (checked `[role=dialog]`: none). The server-side `revision` check only protects against concurrent edits, not
against intent.

Fix: make Apply a `type="button"` that opens a `TaskActionDialog` stating "Rules take effect on every server; a rule
set that does not allow your address, or an empty set, locks you and everyone else out of the panel and of
connections", with the diff against the applied revision; require type-to-confirm when the new list is empty or the
caller's address (the panel can send `actorAddress` from the audit log or ask the server) is not matched by an
allowing rule; block Enter submission. Ask the server for a dry-run or a "would lock you out" check.

### W-02 high - Query cache survives session expiry

Files: `src/bootstrap.ts` (lines 24-31), `src/stores/session.ts` (`expire`, `adopt`), `src/layouts/ShellLayout.vue`
(`signOut` is the only place that calls `queryClient.clear()`).

What is wrong: manual sign-out clears the cache; the expiry path (`onSessionLost` -> `session.expire()` -> redirect to
`/login?expired=1`) does not, and does not cancel in-flight queries. Whoever signs in next in the same tab (a shared
admin workstation, a kiosk, a hand-over after the session timeout) starts with the previous user's cached data, shown
at once on every page that shares a query key, and the previous user's admin-only data (roles, network rules, audit)
stays in memory for `gcTime` (5 minutes). `staleTime` is 5 s, so the stale data is also shown while the refetch runs.
A second variant: another tab signing in as a different user replaces the shared session cookie, so the first tab
keeps showing the old user name and role while GET requests now return the new user's data (mutations fail with
`csrf_token_invalid`).

Trigger: sign in as `admin`, open Security and Databases, let the session expire (I forced `session_expired` from
the mock), sign in as `viewer` on the same tab.

Reproduced: yes. After the expiry and after the viewer signed in, the cache still held `["roles",""]`,
`["databases"]`, `["alerts","open"]`, `["tasks",5]`, metrics and `["cluster"]` with data (listed from the query client
in the page). The viewer is kept out of `/security` by the route guard, so the admin-only roles data was not
displayed; data under keys the viewer may open (databases, cluster, tasks, alerts) was.

Fix: clear the cache and cancel queries in `adopt()` whenever the identity changes (null or a different username),
not in one component; call `queryClient.cancelQueries()` first; key queries by session identity or reload the page on
sign-in; listen to the `storage`/`BroadcastChannel` for sign-in in another tab, or re-fetch `/auth/session` on focus
and compare the username.

### W-03 medium - Grant matrix shows a grant that did not happen

File: `src/components/security/GrantsPanel.vue` (checkbox at ~line 220, `onToggle`, `toggle` mutation).

What is wrong: the checkbox is an uncontrolled native input bound with `:checked="has(row,p)"`. Clicking flips the DOM
state immediately; if the request fails, `has()` still returns the old value, so Vue sees no change and does not
reset the DOM property. The error notice is shown above, but the cell keeps showing the new, false state, and the
matrix is the place an administrator reads to see who may do what.

Trigger: make `POST /grants` fail (forbidden, conflict, network) and tick a box.

Reproduced: yes. With the mock forced to answer 403 for `createGrant`: before click `checked=false`; after the click
and the refetch `checked=true`, with the error notice present.

Fix: control the state (set `event.target.checked = has(...)` in `onSettled`, or render from `toggle.variables`
while pending and from server data afterwards), or key the cell by the server value plus a counter so it re-renders.

### W-04 medium - "Database owner" template applied with one click

File: `src/components/security/GrantsPanel.vue` (template fieldset, `applyTemplate`).

What is wrong: choosing the radio "Database owner" and pressing "Apply template to X" calls
`POST /grants/template-applications` at once. The help text says "Full control of all objects in the database,
including DDL". There is no confirmation and no name of the database in the confirmation (none exists). Read-write
and owner templates are broad grants made on a cell-less control that does not show what changes.

Reproduced: yes. One click produced `POST /api/v1/grants/template-applications` with `template:"owner"`, no dialog.

Fix: `ConfirmDialog` that names grantee and database and states the effect, with type-to-confirm for `owner`.

### W-05 medium - Spoofable names

Files: every place that prints a name: `RolesPanel.vue`, `GrantsPanel.vue` (select options, row labels, matrix
`aria-label`s), `DatabaseDetailPage.vue` (table rows, dialog titles), `ConfirmDialog`/`TaskActionDialog` (`typeToConfirm`
code element and titles), `AuditPanel.vue` (actor, resource), `LogsPage.vue`, `AlertsPage.vue`, `ProblemNotice.vue`.

What is wrong: strings are escaped (no injection) but displayed raw. Bidirectional controls (U+202A-202E, 2066-2069),
zero-width characters, look-alike scripts and ANSI/control characters are not made visible. A low-privileged user who
may create roles or tables can make an object look like another one in lists, in grant dialogs, in
"Drop role ...?" titles and in the audit log. An embedded newline in a log message or alert text collapses into the
same cell, so a fake second log line appears inside one message; ESC, NUL and BEL are passed through.

Reproduced: yes. A role named U+202E + "nimda" is rendered in the Roles table as `admin` (screenshot compared;
`textContent` is `\u202Enimda`). The raw U+202E also reached a workbench result cell, and the ANSI and NUL log
messages reached `textContent` unchanged. The type-to-confirm dialog would print the spoofed name and ask the
administrator to type the visible text, which is not the name.

Fix: one `SafeName` component (and a `safeText` helper) used for every attacker-influenced name and message that
renders ASCII as is and shows other control, bidi, format and (optionally) non-ASCII characters as visible
`<U+202E>` markers with a note when a name contains them; `dir="auto"` plus `unicode-bidi: isolate` on name cells;
show the visible-escaped name in confirmation titles and in the "type to confirm" hint; keep log message cells
`white-space: pre-wrap` with control characters shown as escapes so line breaks are visible as such.

### W-06 medium - Very long strings break the layout

Files: `src/styles/base.css` (`.table`, `.table-wrap`), pages that print names or messages without limits.

What is wrong: no `overflow-wrap`, `max-width` or truncation. One unbroken string stretches the whole table.

Reproduced: yes. With one role named by 5000 characters the Roles `.table-wrap` had `scrollWidth` 39158 px for a
`clientWidth` of 1100 px; the first "Drop" button was at x = 39325 px, so the row's actions (Edit, Disable, Drop) are
unreachable without a long scroll, and a hostile role name can hide the actions of every role below or above it.
The same CSS applies to log messages, alert text, audit resources and workbench cells (not measured separately).

Fix: `overflow-wrap: anywhere` and a `max-inline-size` on name and message cells with the full value in a `title` and
an expand control; sticky action column.

### W-07 medium - Role save shifts "valid until" by the browser's UTC offset

File: `src/components/security/RoleDialog.vue` (line 33 `validUntil: r.validUntil.slice(0, 16)`, line 63
`new Date(form.validUntil).toISOString()`).

What is wrong: the API value is UTC. The dialog puts the first 16 characters of the UTC ISO string into an
`<input type="datetime-local">`, which is interpreted as local time, and converts it back as local time. In any time
zone other than UTC the date is shifted, seconds and milliseconds are dropped, and because the new string differs from
the original, an update is sent even when the administrator changed nothing else. The rest of the panel prints UTC, so
the dialog also disagrees with the table.

Reproduced: yes, browser time zone Asia/Tehran (UTC+3:30), role `analyst` shown as `13 Jan 2027, 18:58:36 UTC`; the
dialog showed `2027-01-13T18:58`; Save without edits sent `PATCH /roles/analyst {"validUntil":"2027-01-13T15:28:00.000Z"}`.

Fix: convert explicitly: show the value in UTC and label the field "(UTC)", or convert with the local offset in both
directions; compare to the original at the same precision and send nothing when unchanged.

### W-08 medium - Workbench: NULL versus the text `NULL`; empty string

File: `src/pages/WorkbenchPage.vue` (`format()`, cell class `muted` for null).

What is wrong: SQL NULL is rendered as the string `NULL`; a text value `NULL` renders identically. The only
difference is the grey `muted` class (colour alone, nothing for a screen reader). An empty string renders as an
empty cell, also not distinguishable from "no data". `bytea` arrives as a hex string without a prefix and large
integers as strings (both per contract), so numbers, strings and hex look the same without reading the type under the
header.

Reproduced: yes (row with `''`, `'NULL'` and a JSON null: cells showed empty, `NULL` and `NULL`).

Fix: render NULL as an italic `<em>NULL</em>` with a visually-hidden "null value", render the empty string as
`""`-style marker with "empty string" for assistive technology, and show strings that equal `NULL` in quotes.

### W-09 medium - Scrollable regions are not keyboard-focusable

Files: `src/styles/base.css` (`.table-wrap { overflow-x: auto }`), every page using `.table-wrap`.

What is wrong: a wide table inside `.table-wrap` can only be scrolled with a mouse or touch; keyboard users cannot
reach columns that are off screen (WCAG 2.1.1). axe reports `scrollable-region-focusable`.

Reproduced: yes. axe in Chrome: `/logs` at 1366 px (light and dark), and at 320 px also `/servers/:id`, `/shards`,
`/replication`, `/ledger`.

Fix: give `.table-wrap` `tabindex="0"`, `role="region"` and an accessible name (the table caption), with a visible
focus style, or avoid horizontal scroll.

### W-10 medium - No reflow at 320 px (400 percent zoom)

Files: `src/layouts/ShellLayout.vue` (topbar), `src/components/LineChart.vue`, `.card`.

What is wrong: at 320 CSS px the whole document scrolls horizontally on every page. Elements beyond the viewport:
`.user` and `.role` (right edge 360 px), the "Sign out" button (right edge 416 px), cards (352 px) and chart figures
(335 px). The Sign out button is therefore off screen at 400 percent zoom (WCAG 1.4.10).

Reproduced: yes (hscroll on all 16 routes in light and dark; element geometry measured on the dashboard).

Fix: wrap the topbar (or move user and sign out into the menu below 600 px), `min-width: 0` on grid and flex
children, charts `max-width: 100%`.

### W-11 low - Workbench behaviour

File: `src/pages/WorkbenchPage.vue`.

(a) The previous result stays on screen when the database selector or the SQL is changed (`result` is cleared only
on error), so a result of database A can sit under a heading that now says database B. (b) No cancel button, and
`timeoutMs` is never sent (server default 30 s applies); the textarea stays editable during the run and Ctrl+Enter is
the only guard against a second run. (c) The contract has no read-only mode, but the page says only "Runs one
statement as your own PostgreSQL role" and does not warn that INSERT, UPDATE, DELETE and DDL are executed (they are
audited by the server). (d) All rows (up to the client limit of 10000) and all cells are rendered into the DOM
without virtualization and without a per-cell length limit; a 100000-character cell rendered but I did not measure
memory. (e) Duplicate column names are used as `v-for` keys in the header (`:key="c.name"`): the page rendered them
(`a text`, `a text`) but duplicate keys are undefined behaviour on update. (f) `v-model.number` on the row limit
yields an empty string when the field is cleared, which is then sent as `rowLimit` (the server rejects it with 400;
reasoned). The statement and results are not stored anywhere (no `localStorage`, no cache beyond component state: the
mutation is not a query).

Reproduced: (e) and the large-cell render only; the rest is reasoned. Large integers: a JSON number above 2^53
(9007199254740993) was displayed as 9007199254740992; the contract says such values come as strings, so this is the
server's job, but the panel cannot detect it either.

### W-12 low - Expiry during a mutation or a task poll

Files: `src/api/queries.ts` (`QueryCache.onError` only), `src/composables/useTask.ts`.

Mutations (`useMutation`) and task polls (`fetchTask`) do not go through the `QueryCache` handler, so a 401 there only
shows a notice ("Session expired") or, for task polls, counts as a lost poll and ends in "Lost contact with the
server ... Reload" after five misses. The redirect then comes only when the next list poll fails. The poll timer
also keeps running in hidden tabs and after sign-out until the owning component unmounts (the dialog stays mounted
across the redirect only if it is outside the router view; reasoned).

Reasoned only. Fix: add a `MutationCache` `onError` with the same `isSessionLost` hook and handle it in `useTask`.

### W-13 low - Hide stops following; some irreversible actions have no typed confirmation

Files: `src/components/TaskActionDialog.vue`, `src/composables/useTask.ts` (`onScopeDispose(stop)`),
`src/components/ServerActions.vue`.

(a) "Hide (keeps running)" closes the dialog, which disposes the poller; `onSettled` never runs, so a failed
"Drop database" or "Remove server" is not reported, and the "done" navigation does not happen. The user must find the
Tasks page. (b) Remove server, hard failover, restore preferred primaries, and rebalance start use a button-only
confirmation (the drop-database, drop-role, enable-ledger and leave-cluster flows use type-to-confirm). Hard failover
"marks the server dead" and is a button with a different label only. (c) Disable/Enable role is a single click with
no confirmation (the server refuses to disable the last administrator).

Reasoned from the code except the double-click check: a double click on the Drop database confirm sent exactly one
`DELETE /databases/reports` (reproduced). Dialog focus trap, Escape and focus return worked (see below).

### W-14 low - Plumbing that hides problems

File: `src/api/queries.ts`.

(a) `ledgerStatusList`: after a 404 it queries each database and silently leaves out any database whose status
cannot be read (`catch {}`), so the Ledger page can show a partial list as complete. (b) `useRoles`/`GrantsPanel` ask
`limit: 500` and ignore `nextCursor`; roles beyond 500 are invisible in the Roles list and in the grantee selector.
(c) `useAllBuckets` follows cursors in a `do ... while` with no page limit; a server that keeps returning a cursor
makes the browser loop forever. (d) Non-JSON 4xx bodies map to `bad_request` and a 401 from a proxy is not treated as
session loss. (e) Unknown problem codes show the generic text and drop `detail`.

Reasoned only.

### W-15 low - Dot segments in names

Files: `src/api/endpoints.ts` (path params), `openapi-fetch`.

`encodeURIComponent('..')` is `..`, which the URL parser removes. A table or database named `..` (a legal quoted
PostgreSQL identifier that a low-privileged user can create) makes `PUT .../tables/../ledger` request
`/databases/shop/schemas/public/ledger`, and `GET /databases/..` request `/api/v1/`. A node check of the URL parser
confirmed the paths above; I did not exercise it in the app. Effect today is a wrong URL (404/405), but it is a
request that does not match the object shown. Fix: refuse or percent-encode `.` and `..` segments (`%2E%2E`) in the
client.

### W-16 low - Modal and live-region details

`AppDialog.vue` relies on `aria-modal` and a keydown trap; the application root is not `inert` or `aria-hidden`
(checked: `#app` `inert` false, no `aria-hidden`), so a virtual cursor and touch screen readers can leave the dialog.
`TaskProgress.vue` creates its `aria-live` region together with its text (many screen readers do not announce text
present at insertion) and updates it every second; the "Lost contact" message and `pollError` are not in a live
region. Reasoned.

## What the server must do for the panel to be safe

The panel sets no security headers itself (it cannot set `frame-ancestors` from a meta tag) and does not document its
needs; the README and `DEPENDENCIES.md` do not mention them. `kingresd` must send:

- `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; font-src 'none'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'` on `index.html` and the assets. Tested: the production build under this policy (login page, sign-in, dashboard shell) produced no `securitypolicyviolation` event. The bundle has no inline script or style, no `eval`, no `data:` URL, no external font or script. What a strict policy would still break: nothing found; `'unsafe-inline'` and `'unsafe-eval'` are not needed. (Vue sets styles through the CSSOM, which `style-src` does not block.) If a later change adds a `style="..."` attribute to a statically hoisted template, `style-src-attr` would block it.
- Framing protection: `frame-ancestors 'none'` (above) and, for old browsers, `X-Frame-Options: DENY`.
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` (task ids and database names appear in the URL path; the redirect parameter carries a path), `Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy` that disables camera, microphone, geolocation.
- Cookie `kingres_session`: `HttpOnly; Secure; SameSite=Strict; Path=/` as the contract states; the panel needs HTTPS or `localhost` for the Secure cookie and says so on sign-in failure. The CSRF token is returned in the JSON body and held in memory only; the server must enforce `X-CSRF-Token` on every non-GET request, and also on `login` or bind login to SameSite (login CSRF is otherwise open).
- Caching: `Cache-Control: no-store` for every `/api/v1/` response (the data is sensitive and role-dependent), `Cache-Control: no-cache` for `index.html`, `Cache-Control: public, max-age=31536000, immutable` only for the hashed files under `/assets/`.
- Serve the SPA fallback (`index.html`) only for non-`/api/` paths, so that an unknown API path yields a JSON problem and not HTML. Answer 401 `unauthenticated`/`session_expired` for every protected API path, and answer `/api/v1/query` with the caller's role.
- Do not serve the Vite dev files (`mockServiceWorker.js`) or the manifest with credentials; `manifest.webmanifest` and icons are static and safe.

## Examined and found sound

- XSS sinks: grep of `src/` found no `v-html`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`,
  `eval`, `new Function`, string `setTimeout`, `postMessage`, `window.open`, data-built `:href`/`:src`, or dynamic
  attribute names; the only `<component :is>` is the dev-only demo hint. `:style` is used only with numbers
  (`ratio`, `percent`) and token colours. Hostile data in role names, table names, alert title and message, log
  messages and workbench cells and column names (markup, attribute breakouts, SVG) rendered as text; `window.__pwn`
  stayed undefined and no `img`/`svg[onload]` element was created on security, databases/shop, alerts, logs and workbench.
- Credential handling: the CSRF token lives in a module variable only; the only storage entries after sign-in were
  `kingres.theme` (localStorage) and `vue-router:scroll` (sessionStorage); the setup token is held in memory and
  cleared after the wizard; no token, password or query is logged to the console or put in a URL; the query cache is
  not persisted; no service worker in the build; the manifest holds no secret. The login redirect only accepts paths
  that start with a single `/`, and `router.push` stays inside the app. The password field is cleared after a failed
  sign-in; password inputs use `autocomplete` `current-password`/`new-password`; no password is shown in dialogs.
- Role gating comes from the generated `operations.generated.ts` (`x-required-role`), the route guard and
  `GateButton` agree, `GateButton` is `aria-disabled` with the reason and not removed from tab order. In the mock,
  `metrics`, `viewer` and `ops` accounts visiting all 17 routes produced no 403 response (no fetch of data the role
  may not see). Security page tabs are all admin-only operations behind one admin gate.
- Destructive flows with a stated consequence and type-to-confirm: drop database, drop role, enable ledger, leave
  cluster. Dialogs capture the object (`dropping = r`, the table object) rather than an index, so re-sorting under the
  dialog does not change the target. Double click on the confirm sent one request. Dialog focus trap, Escape and
  focus return worked in Chrome (Tab cycled input, Cancel, Close; Escape closed and focus returned to "Drop database").
- Problem mapping: `entries: Record<ProblemCode, Entry>` makes the compiler enforce a message for every code; unknown
  codes and non-JSON error bodies (a 502 HTML page was served in the CSP run and the panel stayed usable) are handled;
  network failures become `service_unavailable`; GET retry is limited to 2 retries on 5xx; mutations are never retried
  (mutation M5 was caught).
- Time handling: all API timestamps are displayed as UTC with an explicit "UTC"; invalid dates are shown raw.
  `null` is shown through `NullableValue`/`NotAvailable`; no `?? 0` default for contract-nullable values found.
- Accessibility measured in Chrome with axe-core (wcag2a/aa, 2.1 AA, 2.2 AA, best-practice) on login and 16 routes in
  light and dark at 1366 px: no colour-contrast violation, no missing label, name or role; only the scrollable-region
  issue (W-09). Status badges carry icon plus text. Bucket map cells are `aria-hidden` and `tabindex=-1`, but the
  per-group table and the "Find bucket number" field give a keyboard route to the same information.
- Production bundle and CSP: see W-18 and the server section.
