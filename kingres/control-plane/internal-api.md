# The internal API of kingresd

Status: version 1 (internal protocol version, independent of the public contract
revision). Design: `kingres/docs/design/control-plane-3.md`, decisions D1 and D2.
Implementation: `internal/internalapi`, `internal/pki`.

The internal API is how the servers of one cluster talk to each other. It is
**not** part of the public REST contract and may change with every binary
version; a server refuses a peer that speaks another version.

## Transport and authentication

- A separate TLS listener (setting `internal-listen`, for example `0.0.0.0:8092`).
  The public listener never accepts a client certificate as authentication and this
  listener never accepts a session, a bearer token or a setup token.
- TLS 1.3 only. The server presents the server certificate of its cluster
  (`<data-dir>/pki/server.crt`); the client must present a certificate too
  (mutual TLS).
- A client certificate is accepted only if it is signed by the cluster CA, is
  within its validity, is usable as a client certificate and its serial number is
  not on the revocation list. The common name of the certificate is the caller's
  server id.
- Every certificate is an ECDSA P-256 certificate whose key was generated by the
  server that uses it; the CA only ever sees certificate requests.

## Versioning

Every request carries `X-Kingres-Internal-Version: <n>`. The server answers `409`
with `{"error":"version_mismatch","message":"This server speaks internal API
version 1, the caller \"2\"."}` when the number is missing or different.

## Authorization table

| Call | Policy | Meaning |
|---|---|---|
| `GET /internal/v1/state` | any peer | server id, node state, versions, uptime |
| `GET /internal/v1/leader` | any peer | the server id this server believes to be the manager leader |
| `GET /internal/v1/revoked` | any peer | revoked certificate serial numbers (hex) |
| `GET /internal/v1/resources` | leader | CPU, memory and disks of the server |
| `GET /internal/v1/logs` | leader | local log entries (query: `level`, `from`, `to`, `limit`, `cursor`) |
| `GET /internal/v1/metrics` | leader | latest metric samples |
| `POST /internal/v1/exec` | leader | one statement on a local database through the local socket |

"Leader" means the caller's certificate names the server that holds the primary of
shard group 0, read from the catalog; while that is unknown no leader-only call is
accepted. A path or method that is not in the table is `404`.

The API never executes a path, a program name or SQL taken from a request, with
one exception: `POST /internal/v1/exec`, which is restricted to the leader. Its
body is `{"database": "...", "sql": "...", "rowLimit": 1000}` (SQL at most 1,000,000
bytes, row limit at most 10,000); the server logs the caller, the database, the
length and a hash prefix of the statement, never its text.

## Errors

JSON `{"error": "<code>", "message": "..."}`. Codes: `no_certificate`,
`certificate_refused` (401), `version_mismatch` (409), `not_leader` (403),
`not_found` (404), `bad_request` (400), `statement_failed` (422), `failed` (500).

## Not in version 1

The calls that create, configure, start, stop and remove instances, that apply
network rules and that sign certificate requests (join and add) are specified with
the join and add operations; they are not implemented in this version.
